# “智慧头”声源定位设计

## 目标

在 `head` 板保持实时对话和 Device-Side AEC 的同时，使用左右双麦实时估算正前方半平面内的声源方向。第一阶段提供角度回调和限频日志，不控制电机，也不向外部协议上报。

## 硬件与坐标

- ES7210 MIC1：人头左侧麦克风，收音孔朝正前方。
- ES7210 MIC2：人头右侧麦克风，收音孔朝正前方。
- ES7210 MIC3：连接 ES8311 OUTP/OUTN，作为 AEC 播放参考。
- MIC1 与 MIC2 收音孔中心距：约 48 mm。
- 两个收音孔处于同一水平轴。
- 输出角度：正前方为 `0°`，左侧为负，右侧为正，范围 `-90°~+90°`。

双麦只能估算相对于麦克风水平基线的半平面角度，无法消除前后镜像歧义。

## 音频链路

`HeadAudioCodec` 从当前的 `MIC1 + MIC3` 两通道输入改为：

```text
MIC1(left) + MIC2(right) + MIC3(reference)
```

Codec 对上层报告三个输入通道并启用 ES7210 MIC1、MIC2、MIC3。ESP Codec Dev 选择 TDM slot 0、1、2，输出连续交错的三通道数据。

`AfeAudioProcessor` 已根据输入通道数和参考通道数动态生成格式，因此三通道输入会得到 `MMR`。ESP-SR AFE 使用两路麦克风执行 AEC/BSS/降噪，并继续输出单声道语音给 Opus 编码和实时对话。

声源定位器旁路读取 `AudioService` 重采样后的同一份 16 kHz 原始 `MMR` 数据。定位处理不会改变或占用传给 AFE 的数据。

## 声源定位器

新增独立的 `SoundSourceLocator`，封装 ESP-SR 的 `afe_doa`：

- 输入格式：`MMR`
- 采样率：16 kHz
- 麦克风间距：0.048 m
- 初始角度搜索分辨率：5°
- 时间窗：每通道 1024 点，约 64 ms
- 更新上限：约 15.6 次/秒

定位器累积完整窗口后调用 `afe_doa_process()`。原始 `0°~180°` 结果根据 MIC1/MIC2 左右顺序转换为项目坐标 `-90°~+90°`。首次硬件测试通过左、正前、右三个已知声源位置确认符号方向；如芯片输出方向与预期相反，只调整统一的角度转换，不交换音频通道。

为降低跳动，定位器对最近若干个有效结果执行中值过滤，再进行轻量低通平滑。日志限频输出角度，不在每个音频帧打印。

## 有效性和播放策略

- 设备未播放音频且检测到足够语音能量时，更新角度。
- 无有效语音时保留最后角度，但不产生新结果。
- TTS 或其他音频播放期间停止定位、清空未完成窗口并冻结最后有效角度。
- 播放停止后从新窗口恢复定位，避免将播放前后的样本拼接。

第一阶段使用输入能量门限过滤静音。后续如硬件测试发现噪声触发较多，可将 AFE VAD 状态接入定位器作为第二道门限。

## 配置与边界

声源定位通过独立 Kconfig 开关启用，并仅允许在支持双麦输入的 `head` 板上选择。关闭时不创建 DOA 对象，不增加运行时 CPU 和内存开销。

定位器使用固定大小缓冲区，不在音频热路径中反复分配。DOA 处理与 AFE 共享 16 kHz 输入，但不阻塞网络或 Opus 任务；如硬件性能分析显示音频输入任务超时，则将完整窗口投递到独立低优先级任务。

## 错误处理

- `afe_doa_create()` 失败时记录错误并禁用定位，实时对话和 AEC 继续工作。
- 输入通道数不是三个时拒绝处理并记录一次配置错误。
- 非有限角度、越界角度或静音窗口不会更新最后有效结果。
- 播放状态变化会重置累积窗口，防止污染下一次定位。

## 验证

1. 编译配置：`head` 板可启用声源定位，其他不兼容板不可选。
2. 音频链路：确认 AFE 输入格式为 `MMR`，实时对话和 Device-Side AEC 正常。
3. 通道检查：MIC1、MIC2、MIC3 顺序分别为左麦、右麦、参考。
4. 静态定位：声源放在左侧、正前方、右侧，角度符号和趋势正确。
5. 稳定性：固定声源下角度无高频大幅跳变，日志频率不超过定位更新率。
6. 播放策略：TTS 播放期间角度冻结，播放结束后恢复。
7. 并发：连续实时对话与定位运行时无音频丢帧、看门狗复位或明显延迟增加。
8. AEC：启用定位后回声消除效果不低于当前双通道版本。

## 不在本次范围

- 360° 无歧义定位
- 多声源分离或同时跟踪
- 电机转向控制
- 网络或 MCP 角度上报
- 播放期间对外部说话人的可靠定位
