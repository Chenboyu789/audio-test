# 智慧头（head）

主控为 ESP32-S3 N16R8，无显示屏、无 LED。音频输出使用 ES8311，
输入使用 ES7210：MIC1（左）和 MIC2（右）组成间距 45 mm 的水平
麦克风阵列，同时用于语音采集和声源定位；MIC3 接 ES8311 OUTP/OUTN
作为 AEC 参考，MIC4 不参与当前固件的采集。

声源定位复用 ESP-SR 的 SRP-PHAT，输出正前方半平面角度：左侧为
`-90°`，正前方为 `0°`，右侧为 `+90°`。只有检测到足够强的近端语音
时才更新结果，设备播放语音期间暂停输出。

ES7210 实际输出顺序为 `MIC1、MIC3参考、MIC2`（`MRM`）。唤醒和实时
对话提取通道 0/1，转换为 `MR` 后执行单麦克风处理和 AEC；定位提取
通道 0/2，并对极性相反的 MIC2 做软件反相后送入 SRP-PHAT。

## 构建

```powershell
python scripts/release.py head
```

设备端 AEC 默认启用。板载按键功能已取消。

## PCA9685 舵机驱动

PCA9685 使用独立 I2C 总线，地址为 `0x40`，PWM 频率为 50 Hz：

- SDA：GPIO8
- SCL：GPIO7
- 电源使能：GPIO0，低电平有效

GPIO0 已改作 PCA9685 电源使能，原 Boot 按键及其单击、双击功能全部取消。
GPIO0 同时是 ESP32-S3 启动绑带引脚，硬件必须保证复位采样期间保持高电平，
否则设备可能进入下载模式。

PCA9685 初始化成功后，CH1（第二路输出）上的舵机会执行一次
`0° → 90° → 180° → 90°` 测试，每步间隔约 800 ms，最后保持在 90°。

## 硬件验证

首次烧录后应确认：

1. ES8311、ES7210 均能正常初始化。
2. 扬声器和 PA GPIO42 工作正常。
3. 输入的三个通道依次为 MIC1、MIC3 回采和 MIC2。
4. MIC4 不进入采集数据流。
5. 在设备前方约 1 m 处，从左、中、右讲话时，日志中的角度方向正确。
6. 播放 TTS 时不输出新的定位结果。
7. 播放 TTS 时，开启 AEC 后语音通道中的扬声器回声明显降低。
8. 设备正常启动且不会进入下载模式。
9. PCA9685 CH1 输出约 50 Hz PWM，舵机只执行一次启动测试动作。
